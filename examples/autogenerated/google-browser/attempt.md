# First-party browser execution qualification

The six real ICU captures at ICU4f365 and independent run41573122647 contain
JavaScript-required HTML and no qualifying public destinations. Native HTTP
does not execute those instructions. This bounded probe tests the explicitly
separate Android WebView acquisition option before selecting a production
adapter. It is qualification equipment, not an IB application replacement,
result reader, source-admission shortcut or accepted Google implementation.

The checked Idriç Activity owns a fixed public once-encoded query and an
allowlist of first-party Google search/observed continuation routes. A separate
checked framework-class plan declares WebViewClient, ValueCallback and Runnable
interfaces. The existing DEX backend emits all candidate DEX. The C boundary
only invokes Android SDK calls, validates/copies the callback's UTF-16 into
bounded UTF-8 files and schedules up to30 read-only DOM observations.

The normal first-party page executes under the platform's unchanged strict TLS
and Safe Browsing behavior. No SSL callback override, manual challenge answer,
cookie copying, provider substitution or consent action is supplied. A main
frame outside the checked search/continuation routes is refused. Ordinary
WebView session cookies remain in its private profile. No external browser or
Java/Kotlin implementation is involved.

Each saved DOM is an explicitly browser-rendered derivative. Its offsets and
digest describe only its UTF-8 serialization. Original browser network bytes,
HTTP status, original body offsets and ICU identity are not fabricated.
Independent ai-ci classification must examine the saved snapshots and exact
resolved URLs. Even a positive probe does not qualify canonical Arena source
admission, native result display/touch, history, caller authentication or the
production APK. If actual execution provides results, those integration steps
remain required. If it reaches verification, it must remain a refusal.

The first checked Activity emission refused an unconstrained
`SavedStateReference`: a lifecycle annotation alone does not validate an
opaque DEX source ABI. The source now binds it through the maintained typed
Bundle-to-Object cast. The same pinned backend emits the Activity successfully;
the canonical frontend compiles and executes the typed class generator.
Both outputs are independently disassembled. This is host structural evidence,
not SDK, ART, browser execution or public-result acceptance. No runtime or
language fallback was selected.
