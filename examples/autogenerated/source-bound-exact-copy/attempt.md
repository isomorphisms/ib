# Program attempt: source-bound exact Copy

Status: `PARTIAL` — source checking and pure compiler normalization pass;
native clipboard integration remains blocked.

## Purpose

SUN IB-D05 extends the existing `IB.DisplayRepair.CopyButton` with validated
source/range identity, cheap candidate discovery and browser-owned disable
policy. A renderer may disappear; a rebuilt control must copy the same retained
semantic source span without cleaning or reparsing presentation text.

## Intended behavior

Candidates reference an accepted S06 `FragmentGraph`, its existing source
binding, a stable target/fragment identity, and a half-open Unicode-code-point
subrange. Preparation resolves exact source characters into the existing
`CopyButton`. Activation checks the current policy, source binding, range and
payload again before producing a clipboard handoff. Producing that handoff is
not a clipboard write. Explicit/code/preformatted candidates need no model.

## Type-system sketch

### Values and domains

- `RevisionedSource`, `FragmentGraph`, `SourceFragment` and `SourceCoordinate`
  are S06/`IB.Occurrence` objects, not new Copy-owned source or fragment models.
- A candidate's five-field `source_binding` is a source/revision reference,
  not an authentication credential or a computed digest proof.
- The trusted browser context supplies the site identity and current graph;
  a renderer candidate cannot choose which site disable policy applies.
- `CopyPolicy` contains global disable and exact canonical site disables.
- `copy_refusal` distinguishes disabled policy, unsupported detection, malformed
  identity, stale source, absent fragment, invalid range, changed payload and
  missing clipboard capability.

### Types and signatures

`prepare_copy : CopyPolicy → Text → FragmentGraph → CopyCandidate →
Either copy_refusal PreparedCopy`

`clipboard_handoff : CopyPolicy → Text → FragmentGraph → Text → Bool → PreparedCopy →
Either copy_refusal DisplayRepair`

`cheap_candidates : List CopyCandidate → List CopyCandidate`

The final `DisplayRepair` is the already-owned `CopyButton`; its payload is
resolved from the retained authoritative source, with no whitespace transform.

### Actions and effects

All core functions are pure. Platform clipboard permission, actual clipboard
write/result, retained-file checksum verification and trusted-control painting
belong to separate adapters. No fetch, DOM mutation, source write, private
corpus collection or message transmission occurs in this attempt.

### Laws, invariants, and errors

- Exact output equals the canonical source's selected code points, including
  spaces, tabs, CR/LF, combining characters, non-BMP characters and valid empty
  subranges.
- Target ids never define source identity; equal bytes from another source
  or a changed decoder/digest remain a different binding.
- A candidate cannot escape its declared canonical fragment or supply its own
  replacement payload. A stale prepared control cannot write after a revision
  change or after policy is disabled.
- Cheap discovery is separate from activation and never performs a write.
- The passed graph must be accepted by S06; its byte-owning adapter must actually
  verify the digest and decoder provenance. The Copy core cannot make that fact
  true from an arbitrary claimed string.

### Runtime and backend boundary

Use the actual clean Idriç compiler `ff4d852862a3942592f8ade9afde8d409d9803be`
for `--check` and pure `--client` normalization only. No Chez, Java, Gradle or
generated-C consumer build is permitted. ICK/NDK consumer code generation and
the D01/D02 native clipboard/view path are separate unqualified boundaries.

## Result or failure

The first `--check` failed because `choice CopyRefusal one_of` uses an uppercase
choice type name. The current frontend requires lower snake_case choice names;
the maintained type is corrected to `copy_refusal`. This was a source grammar
failure, not a missing source/fragment capability or backend execution failure.
Further check/normalization evidence follows below when executed.

The next `--check` found that `FragmentGraph.source` is correctly private in
S06. D05 requested exported read-only `graph_source`/`revision_text` accessors
from that owner rather than exposing or duplicating the checked graph model.

Loading an example outside `--source-dir src` was correctly refused; using its
actual example source directory after checking the core fixed that invocation.
Both source checks then exited 0. All 25 named cases normalized to `True`.

The maintained whitespace-normalizing mutation patch was applied in a separate
detached worktree. It checked successfully, then normalized exactly three
cases to `False`: whole-code exactness, exactness under an unrelated site
disable, and retained-graph reconstruction exactness. All other cases remained
`True`. Reversing the patch, rechecking the module and normalizing again restored
all 25 results to `True`. No maintained source was left mutated.

The compiler normalizer exits 0 for a successfully evaluated expression even
when that expression contains `False`; rejection is the compared named-case
matrix, not a claimed nonzero normalizer status. This is a local executed
normalization corpus, not a newly protected CI gate.
