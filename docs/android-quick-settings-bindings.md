# Android Quick Settings bindings

IB/Pensieve has a source dependency on the reusable declarations in
`vendor/android-NDK/quick-settings/idric`. The gitlink fixes the dependency
revision; `.gitmodules` records its canonical repository. Initialize that
submodule before consuming the binding package.

This change pins upstream candidate revision
[`d0d0eb6b702538c2806757b01a078da21dd41c6b`](https://github.com/isomorphisms/android-NDK/commit/d0d0eb6b702538c2806757b01a078da21dd41c6b).
The earlier declaration-only revision was
[`65769fd68a30a26e0dacd2d0f9ba182850857e86`](https://github.com/isomorphisms/android-NDK/commit/65769fd68a30a26e0dacd2d0f9ba182850857e86).

Import `Android.QuickSettings` directly. Its package name is
`idric_android_quick_settings`, declared in
`idric-android-quick-settings.ipkg`, and its source root is
`vendor/android-NDK/quick-settings/idric/src`. Android binding types and foreign
declarations remain owned by android-NDK. IB has no duplicate wrapper API.

The consumer example at
`examples/autogenerated/quick-settings-bindings/QuickSettingsBindings.idric`
checks source access to the actual upstream declarations. Its accompanying
`attempt.md` records the compiler, dependency, command, and evidence scope.
The original declaration-only dependency and direct consumer passed source checking.
Typecheck the dependency package first, then expose its checked-module
`build/ttc` directory through `IDRIS2_PATH` when checking an IB consumer.
`IDRIS2_PATH` searches checked modules; it is not an additional raw source root.

A separate executable acceptance source at
`examples/autogenerated/quick-settings-runtime/PensieveQuickSettingsRuntime.idric`
calls those public wrappers directly. It covers framework object forwarding,
state projection, ordered setter/update calls, all six add-request arguments,
and independent callback code/constructor observations. Its exported method
names match upstream's external `QuickSettingsRunner`; the example's `main`
performs no platform action.

That source and the dependency package passed historical Idriç source checks
against the earlier published backend candidate
[`3fb6a75d8cffe2f9bff77ae58754e7344d65e20a`](https://github.com/isomorphisms/android-NDK/commit/3fb6a75d8cffe2f9bff77ae58754e7344d65e20a)
in [isomorphisms/android-NDK #20 — Lower checked framework calls and IO directly to DEX](https://github.com/isomorphisms/android-NDK/pull/20).
Current candidate `d0d0eb6` repairs the verifier's compiler/library dependency
set and caches the successful compiler/API build; its binding and fixture
sources are unchanged from `3fb6a75`. The earlier source-check receipt keeps
its original revision and commands. The current candidate is recorded in the
gitlink so hosted verification uses that exact revision. Runtime acceptance
remains pending. The example's `attempt.md` and `source-check.txt` distinguish
its checked source from its pending DEX emission and ART execution. Upstream
runtime evidence is a separate result and cannot establish execution of this
IB-owned source by itself.

The `Pensieve Quick Settings bindings` workflow checks the exact PR head and
builds the compiler and upstream driver from their pins. It then compiles the
IB-owned source with that driver and requires fresh artifacts, clean compiler
logs, independent DEX parsing, and a byte-for-byte match with upstream's
Quick Settings candidate. The upstream verifier owns all four ART runners.
The final IB receipt requires the emitted IB DEX to match both the upstream
candidate and the bytes pulled back from the emulator. That receipt describes
shared runner execution of identical bytes; it does not claim a separate IB
Android lifecycle. Hosted results remain pending until the workflow runs.

This provides no tile purpose yet. No tile registration, label, icon, click
action, add-tile prompt, background service, or application behavior is selected
by this dependency. Any future use must explicitly supply the platform-owned
service/object references and respect each declaration's Android API floor.
The reference domain includes Java null; these types do not establish
non-nullness or lifecycle validity.

Source checking does not prove DEX lowering, Android invocation, packaging,
installation, or physical-device behavior. Those boundaries need their own
evidence when a consumer action is chosen.
