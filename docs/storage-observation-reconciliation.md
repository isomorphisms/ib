# Reconcile observations before app storage admission

`IB.StorageCapabilities` is one Idriç consumer of the existing five-column
versioned app/shell reports. It retains their rows as input values and applies
the existing `IB.StorageAdmission` ledger and publication contract. It performs
no probe, file mutation, directory scan, process launch or device operation.

`capability_rows` validates the header and row shape. `ledger_from_report`
requires unique metadata for the selected app root. `publication_from_reports`
checks the internal safety floor and selected-root ledger, then calls the
existing `publication_for`. Its result includes both reservations, so internal
work cannot vanish from subsequent commitment accounting.

Every bound observation must preserve:

- the explicit per-installation identity, source head, app UID and observation time;
- selected root's backend, media UUID, volume generation, observation identity,
  and known capacity-pool relationship;
- root-specific measured capacity and bounded app-UID writer evidence;
- expected backend/media/observation identities of the actual publication location.

Root identities remain attributes of the existing `app_storage_root` row.
They do not become new browser resource, tab, event or task identities. Android
framework UUID alone is not a media generation. A path or slot reused by
replacement media cannot inherit a previous generation's admission.

Missing/duplicate bindings yield unknown capacity. Present conflicting or expired
bindings yield stale observation. Writer denial, read-only, absence, unknown,
reported and simulated states cannot become measured writable storage. The
only successful writer input is a trusted selected-root `app_storage_writer`
row with `status=measured`, `authority=android-app`, and
`value=bounded-write-pass`; a page/model claim cannot supply those observations.
Authenticating the producer/receipt remains the caller's boundary, not a claim
that arbitrary TSV strings provide attestation.

Only one selected capacity row is used; shell `df` and app aliases are never
summed. Known aliases use the smaller available amount, stricter floor and
larger outstanding commitment, with new internal peak charged once. Unknown
pool relationship cannot establish independence. Integer byte quantities retain
capacities above 4 GiB. Malformed decimals or available bytes exceeding total
capacity refuse.

## Current producer contradiction

The current app report has no installation/time/media-generation/pool binding
and supplies `framework-root-plus-canWrite; no test write performed`. It cannot
establish the evidence above. The current shell report keeps app writer access
and pool relationship unknown; shell visibility cannot authorize app writes.
Both exact current shapes are refusal cases in the semantic fixtures. No
normalizer substitutes a model name, path, remembered SD capacity or Cat Food
inventory timestamp for a missing current app observation.

Successful fixtures append required root attributes and a bounded-writer result
to the existing row vocabulary. They demonstrate the consumer contract; they
are not evidence that the producer performs those operations. Completing
production admission therefore still needs the source/time/media join and the
separately authorized bounded app writer proof from the producer's owner.

## Acceptance

`examples/autogenerated/storage-reconciliation/ReconcileStorage.idric` covers
wide capacity, distinct installations, shell-only authority, reported/simulated
writer evidence, freshness, changed generation, unknown aliases, duplicate
capacity, internal-low/SD-large refusal, exact publication reservations,
shared-pool budget refusal, and actual framework/shell report refusal.

`tests/test_storage_reconciliation.grease` checks source and asks the maintained
compiler to normalize those semantic results. It does not select a code
generator, create a consumer executable, or claim physical-device execution.
The separate ICK/NDK qualification and producer evidence gates remain open.
There is no appendFAT mount, raw SD write or restoration prerequisite.
