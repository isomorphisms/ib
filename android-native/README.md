# Native Idriç reader

The application path is checked Idriç -> direct DEX -> Android framework views.
`examples/autogenerated/native-reader/NativeReader.idric` owns the temporary
text/action adapter; XML owns its resources. The checked Activity emitter calls
the framework superclass before the create export and forwards the Activity
receiver and clicked view to the checked action export.

The reader wraps supplied text in a selectable native TextView. It accepts
Android plain-text shares and an explicit pasted-text input. The Sources
button shows/hides that input; Read copies its exact text into the reader.
This small view does not own browser state or interpret HTML as a document.

The legacy Java/Gradle prepaint and WebView trees and their build workflows
are removed on this migration line. Their historical source remains at IB
41d4cae9c15e42d3b0b4ed4ed957ba86a7ac396a. No Java fallback is selected.
Existing Idriç semantics and Grease acquisition remain in place.

## Incomplete migration

This is a partial migration. The native reader is not a replacement claim for
retained-source projection, image blocks, acquisition, Binder workers,
Longview sessions or durable navigation. The actual source-title consumer in
`examples/autogenerated/native-source-projection/` reaches existing
IB.Information/IB.RecoveredInformation, then the checked backend rejects it:
`DEX unpack cannot reinterpret a source object as an integer: source constructor _builtin.NIL in checked helper IB.Information.tokenize_chars`.
The continuation passes source checking and materializes the initial Boolean
flag; the existing character/token accumulator is now the first DEX blocker.
No Java parser or competing document model replaces that rejected attempt.

A one-off replay of this unchanged pure export with canonical android-NDK
`973c24bc0b4eab6f3c88699102f7cb0e7fd8951f` still returns compiler exit 1 and
emits no DEX. A separate command-style IO diagnostic can now emit the same
existing recovery/title path through that backend's managed runtime, and its
DEX independently decodes. It has not executed under ART and does not provide
the pure callable export or Activity bridge. See the retained-source
`attempt.md`, `replay.grease`, and source-bound replay receipt. The native reader
pin remains unchanged.

Full source recovery needs a checked runtime representation for the existing
source collections/records at its callable-export boundary, followed by
integration of the existing workers and storage owners. Browser features
retired from the Java harness must not be
marked delivered by this text-view control. The Idriç/DEX diagnostic and view
paths also retain their separately recorded compiler-bootstrap/build-policy
debt. Keep this line draft until those gates and physical acceptance pass.

## Identity and package checks

Package `org.isomorphisms.ib.prepaint`, label `IB Prepaint`, minimum SDK 26,
target SDK 36, versionCode 3. Signing uses the existing Wegert public test
keystore at 89dcfb840cec1a66ee04c7f7404954cbd6c09839 with certificate SHA-256
`de9b1d47c5a65e6d46a204b79dd9ee566b9d3c9832ba81ebc4213d3392e92ff9`.
Never generate another signer. The installed C67 package/version/certificate
and replacement installation have not been inspected or accepted here.

Source absence, checked DEX emission, independent DEX parsing, resource/APK
packaging and signer verification are separate from ART launch, visible text,
click behavior and physical C67 evidence. Signing-tool execution is Android
package metadata work, not Java application compilation.
