# Native Material 3 reader qualification

The Activity, view construction, text behavior and source handoff come from
checked Idriç under `src/IB/Android`. The wrapper in
`examples/autogenerated/material-reader-screen` declares the bounded platform
lifecycle and callback bridges. Android framework widgets provide the actual
views. This shape needs no Java/Kotlin application or Gradle build.

Presentation is application-owned XML. Dark surface, foreground, primary and
on-primary colors and TitleLarge/BodyLarge/LabelLarge typography come from the
pinned Material Components 1.14.0 design-token resources. The platform
Theme.Material parent supplies window compatibility; the explicitly applied
roles, dimensions and button shape supply this Material 3 presentation. No
Material Components or Compose application bytecode is linked into this APK.
Framework TextView line heights are set explicitly in scaled pixels because
text appearances alone do not supply MaterialTextView's line-height behavior.

The prepared reader body is IB's own README at
`9027d5ea0ce8718b0337b4cd3d16c0549dc2b2ed`. Its exact source address is carried
by the native source button and handed to Android's chooser after a click.
This is a bounded source snapshot, not a live Pensieve/store reader, browser
tab/history implementation, Markdown parser or network acquisition service.

The disposable package is `org.isomorphisms.ib.material3`, version code 1,
minimum SDK28 and target SDK34. It is separate from the existing prepaint
package. The certificate is the existing public test lane,
`de9b1d47c5a65e6d46a204b79dd9ee566b9d3c9832ba81ebc4213d3392e92ff9`,
from the pinned public Wegert test keystore. No new signer is generated.
Independent build-policy promotion, central package registration, update
compatibility and physical-device acceptance remain separate.

`build.grease` takes verified absolute paths for IB, android-NDK, Idriç, the
actual checked driver/modules, Android SDK, the public test keystore, independent
baksmali and fresh evidence. It materializes the actual production sources,
emits fresh DEX twice, independently decodes both, compares recovery bytes,
and invokes android-NDK's checked Activity candidate packager. Android execution
uses the separate text and screen observers; build success does not supply it.

Active Android acceptance lives in android-NDK's existing Checked DEX framework
effects workflow. It builds this pinned IB screen, runs registered Android
Instrumentation against the actual ReaderText source and three production
mutants, then requires the actual Activity's display, scrolling, two widths and
chooser delivery to an independent source-address receiver. The receiver is
first started without source data and must show failure, preventing a seeded
success marker. Installed APKs are pulled and compared with the build inputs.
Two disposable observer packages supply the chooser choices; the factory Chrome
package is disabled only in that emulator because its restored browser preference
otherwise dispatches directly. Actual chooser selection must deliver ACTION_VIEW
and the exact pinned address to the independent receiver.
The older `run-android.grease` and standalone `verify-art.grease` are failed
software-emulator diagnostics retained for history.

See the [qualification receipt](../qualification/android-view/material-screen-receipt-2026-10-14.md)
for exact artifacts, failures and acceptance boundaries.
